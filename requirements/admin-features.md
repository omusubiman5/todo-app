# 管理者機能要件仕様書

## 概要
todo-appにシステム管理者機能を追加し、ユーザー管理、セキュリティ管理、システム監視機能を提供する。

## 1. 機能要件

### 1.1 ユーザー管理機能
**優先度: 高**

#### 1.1.1 ユーザー一覧・検索
- 全ユーザーの一覧表示
- メールアドレス、登録日、最終ログイン日での検索・フィルタリング
- ページネーション対応（50件/ページ）
- ユーザー詳細情報の表示

#### 1.1.2 パスワード管理
- **管理者によるパスワードリセット**
  - 対象ユーザーにリセットメール送信
  - 緊急時の強制パスワード変更要求
  - パスワード履歴管理（過去5回分）

#### 1.1.3 アカウント制御
- アカウントの一時停止/有効化
- アカウント削除（論理削除）
- ログイン失敗によるロック解除
- セッション強制終了

### 1.2 セキュリティ管理機能
**優先度: 高**

#### 1.2.1 ログイン監視
- 失敗したログイン試行の監視
- 異常なアクセスパターンの検出
- IP アドレス別ブロック状況
- ブルートフォース攻撃の検出と対策

#### 1.2.2 セキュリティポリシー設定
- パスワード強度ポリシー設定
- ログイン試行制限の調整
- セッションタイムアウト設定
- IP ホワイトリスト/ブラックリスト管理

### 1.3 システム監視機能
**優先度: 中**

#### 1.3.1 監査ログ
- ユーザーアクション履歴
- 管理者操作ログ
- システム設定変更履歴
- データエクスポート機能

#### 1.3.2 システム統計
- ユーザー登録数推移
- アクティブユーザー数
- タスク作成・完了統計
- チーム利用状況

### 1.4 通知・アラート機能
**優先度: 中**

#### 1.4.1 セキュリティアラート
- 異常ログイン検出時の通知
- システムエラー発生時の通知
- 定期的なセキュリティレポート

## 2. 非機能要件

### 2.1 セキュリティ要件
- **認証**: システム管理者専用認証
- **認可**: 細分化された権限管理
- **データ保護**: 個人情報の適切な暗号化
- **監査証跡**: 全ての管理者操作を記録

### 2.2 パフォーマンス要件
- ユーザー一覧表示: 3秒以内
- 検索機能: 2秒以内
- パスワードリセット: 1秒以内

### 2.3 可用性要件
- 管理者機能の可用性: 99.9%
- 通常ユーザー機能への影響: 最小限

## 3. ユーザーストーリー

### 3.1 システム管理者として
```
As a システム管理者
I want to ユーザーのパスワードをリセットする
So that ユーザーがアカウントにアクセスできない問題を解決できる

Acceptance Criteria:
- ユーザー一覧からユーザーを選択できる
- パスワードリセットメールを送信できる
- リセット完了を確認できる
- 操作履歴が記録される
```

### 3.2 セキュリティ管理者として
```
As a セキュリティ管理者
I want to 異常なログイン試行を監視する
So that セキュリティ脅威を早期に検出できる

Acceptance Criteria:
- リアルタイムでログイン失敗を監視
- 異常パターンの自動検出
- アラート通知の送信
- 対象IPの自動ブロック
```

## 4. 技術要件

### 4.1 アーキテクチャ
- **フロントエンド**: Next.js 15 + React 19
- **バックエンド**: Supabase (PostgreSQL + Edge Functions)
- **認証**: Supabase Auth + RLS
- **UI**: Tailwind CSS + Radix UI

### 4.2 データベース設計
```sql
-- システム管理者テーブル
CREATE TABLE system_admins (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES auth.users(id),
  role admin_role NOT NULL,
  permissions JSONB,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  created_by UUID REFERENCES auth.users(id)
);

-- 管理者操作ログ
CREATE TABLE admin_audit_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  admin_id UUID REFERENCES system_admins(id),
  action TEXT NOT NULL,
  target_type TEXT,
  target_id TEXT,
  details JSONB,
  ip_address INET,
  user_agent TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- セキュリティ設定
CREATE TABLE security_settings (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  setting_name TEXT UNIQUE NOT NULL,
  setting_value JSONB NOT NULL,
  updated_by UUID REFERENCES system_admins(id),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 4.3 API エンドポイント
```
/api/admin/users          - ユーザー管理
/api/admin/security       - セキュリティ管理
/api/admin/audit-logs     - 監査ログ
/api/admin/settings       - システム設定
/api/admin/notifications  - 通知管理
```

## 5. セキュリティ考慮事項

### 5.1 認証・認可
- 多要素認証（MFA）必須
- 管理者セッションの短時間タイムアウト
- 特権操作の追加認証要求

### 5.2 データ保護
- 個人情報の仮名化表示
- パスワードハッシュの非表示
- 機密データの暗号化

### 5.3 監査・コンプライアンス
- 全操作の詳細ログ記録
- GDPR対応のデータ処理
- 定期的なセキュリティ監査
